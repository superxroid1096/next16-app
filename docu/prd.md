## 1. ملخص وربط بالـ BRD

الـ BRD بيحدد **إيه المطلوب**، والـ PRD ده بيحدد **هنبنيه إزاي وبأي ترتيب**. كل ميزة هنا مربوطة برقم المتطلب (FR) بتاعها في الـ BRD، وجدول الربط في القسم 10.

**اللي اتحدد في الـ BRD وبيحكم التنفيذ:**
- عربي (RTL) أساسي وإنجليزي، ولايت/دارك حسب جهاز الزائر.
- لوحة تحكم لإدارة المحتوى فقط، والمحتوى بنسختين بيتكتبوا يدويًا.
- المشاريع: كارت + صفحة تفاصيل + صور متعددة.
- آراء الزوار بتتعتمد من اللوحة قبل النشر.
- فكرة "الموقع بيبدأ بسؤال" (وضع الزيارة: توظيف / عميل / تقني).
- مفيش SEO، ومفيش إيموجي، والمهارات نص من غير أشرطة.

**اللي بره النطاق (زي الـ BRD):** SEO، التحكم في شكل الموقع من اللوحة، رسائل التواصل داخل اللوحة، إحصائيات الزوار، الترجمة التلقائية، المدونة، أكتر من أدمن، الدومين والاستضافة.

## 4. نموذج البيانات

**الحقل ثنائي اللغة:** كل نص بيتخزن كـ `{ ar: string, en: string }`.

```ts
type L10n = { ar: string; en: string };
```

### 4.1 الكيانات

| الكيان | الحقول الأساسية | ملاحظات |
|---|---|---|
| **SiteSettings** (مستند واحد) | الاسم `L10n`، المسمى `L10n`، الجملة الرئيسية `L10n`، النبذة `L10n`، الصورة الشخصية، حالة التوفر (bool + نص `L10n`)، واتساب، إيميل، LinkedIn، GitHub، روابط إضافية | يغطي التعريف والتواصل |
| **Project** | `slug` (فريد)، `title`، `summary`، `description`، `role`، `challenge`، `solution`، `result` (كلها `L10n`)، `techs: string[]`، `githubUrl`، `liveUrl`، `modes: ('hire'|'client'|'tech')[]`، `featured`، `status` (`draft`|`published`)، `order`، `images[]` | الصور مدمجة جوه المستند |
| **Project.images[]** | `publicId`، `url`، `width`، `height`، `alt: L10n`، `isCover`، `order` | صورة غلاف واحدة بس |
| **SkillGroup** | `name: L10n`، `items: string[]`، `order` | المهارات نص عادي من غير مستويات |
| **Experience** | `company`، `role`، `description` (`L10n`)، `startDate`، `endDate` (اختياري = حالي)، `order` | |
| **Certificate** | `title`، `issuer` (`L10n`)، `date`، `verifyUrl`، `order` | |
| **Feedback** | `name`، `roleOrCompany`، `message`، `status` (`pending`|`approved`|`rejected`)، `locale`، `createdAt` | النص نص عادي، من غير HTML |
| **RateLimit** | `key` (هاش IP + نوع العملية)، `count`، `expiresAt` | فهرس TTL على `expiresAt` |
| **Admin** | `email` (فريد)، `passwordHash` | بيتعمل بسكريبت، مفيش تسجيل عام |

### 4.2 مثال: Project Schema

```ts
// src/lib/db/models/project.ts
import "server-only";
import { Schema, model, models } from "mongoose";

const l10n = { ar: { type: String, default: "" }, en: { type: String, default: "" } };

const imageSchema = new Schema({
  publicId: { type: String, required: true },
  url: { type: String, required: true },
  width: Number,
  height: Number,
  alt: l10n,
  isCover: { type: Boolean, default: false },
  order: { type: Number, default: 0 },
}, { _id: true });

const projectSchema = new Schema({
  slug: { type: String, required: true, unique: true },
  title: l10n, summary: l10n, description: l10n,
  role: l10n, challenge: l10n, solution: l10n, result: l10n,
  techs: [String],
  githubUrl: String,
  liveUrl: String,
  modes: { type: [String], enum: ["hire", "client", "tech"], default: [] },
  featured: { type: Boolean, default: false },
  status: { type: String, enum: ["draft", "published"], default: "draft" },
  order: { type: Number, default: 0 },
  images: [imageSchema],
}, { timestamps: true });

projectSchema.index({ status: 1, order: 1 });

export const Project = models.Project || model("Project", projectSchema);
```

### 4.3 قواعد عامة للبيانات
- أي قراءة للموقع العام بتستخدم `.lean()` وبتتحول لكائن عادي (DTO) قبل الرجوع، لأن كائنات Mongoose مش قابلة للتسلسل ومينفعش تتكاشّ.
- `_id` بيتحول لنص قبل ما يطلع من طبقة البيانات.
- اتصال مونجو بيتخزن في `globalThis` عشان إعادة التحميل في التطوير ما تفتحش اتصالات كتير.
- لو نسخة لغة فاضية: العنصر بيظهر بالعربي كبديل (FR-A-13 بيظهر تحذير في اللوحة).

## 6. استراتيجية العرض والكاش

### 6.1 المبدأ
- الموقع العام: بيانات من مونجو، متكاشة بـ `"use cache"` ومعاها `cacheTag`، واللغة بتتبعت كمعامل للدالة عشان تدخل في مفتاح الكاش.
- اللوحة: ديناميك بالكامل، من غير كاش.
- بعد أي تعديل من اللوحة، الـ Server Action بتلغي tags المتأثرة (`updateTag` أو `revalidateTag` حسب الحالة). في Next 16 دالة `revalidateTag` بتاخد معامل تاني (ملف تعريف الكاش)، وكده وقت التنفيذ نراجع التوقيع الحالي في التوثيق الرسمي.

### 6.2 مثال شكل دالة قراءة

```ts
// src/lib/data/public-queries.ts
import "server-only";
import { cacheTag } from "next/cache";
import { connectDB } from "@/lib/db/connect";
import { Project } from "@/lib/db/models/project";
import { tags } from "@/lib/tags";

export async function getPublishedProjects() {
  "use cache";
  cacheTag(tags.projects);
  await connectDB();
  const docs = await Project.find({ status: "published" }).sort({ order: 1 }).lean();
  return docs.map(toProjectDTO); // كائنات عادية، _id كنص
}
```

> داخل `"use cache"` ما نستخدمش `cookies()` أو `headers()`. أي قيمة محتاجينها بتتبعت كمعامل.

| Tag | بيتلغي لما |

| `settings` | تعديل التعريف أو التواصل |

### 6.4 وضع الزيارة والثيم بدون ما الصفحة تبقى ديناميك
1. سكريبت صغير مضمّن في `<head>` بيقرأ `localStorage` ويحط `data-mode` و`data-theme` على `<html>` قبل أول رسم (مع `suppressHydrationWarning` على `<html>`).
2. ترتيب الأقسام بـ CSS `order` على حاوية Flex، حسب `data-mode`.
3. ترتيب كروت المشاريع: كل كارت بياخد متغيرات `--o-hire` و`--o-client` و`--o-tech` محسوبة في السيرفر (المشاريع الموسومة بالوضع الأول، وبعدها الباقي بترتيب `order`)، والـ CSS بيطبقها:

```css
html[data-mode="hire"]   .project-card { order: var(--o-hire); }
html[data-mode="client"] .project-card { order: var(--o-client); }
html[data-mode="tech"]   .project-card { order: var(--o-tech); }
```

## 7. الأمان

### 7.1 تسجيل الدخول والجلسة
- الأدمن بيتعمل بسكريبت `create-admin.ts` فقط. مفيش صفحة تسجيل.
- كلمة المرور مشفرة بـ `bcryptjs` (cost 12).
- الجلسة: JWT موقّع بـ `jose` (HS256) في كوكي `httpOnly` و`Secure` و`SameSite=Lax`، ومدتها محددة.
- `proxy.ts` بيعمل توجيه تفاؤلي لـ `/admin/login` لو مفيش جلسة. **مش هو خط الدفاع الأساسي.**
- **خط الدفاع الأساسي:** دالة `verifySession()` في `lib/auth/dal.ts` بتتنادى في بداية كل صفحة محمية وكل Server Action وكل Route Handler في اللوحة.
- محاولات الدخول الفاشلة محدودة بـ Rate limit (جدول `RateLimit`).

### 7.2 المدخلات
- كل Server Action بتعمل `safeParse` بـ Zod قبل أي كتابة، وبتتحقق من الجلسة قبل التحقق من البيانات.
- الآراء: حد أقصى للطول، نص عادي فقط (React بيعمل escape، وما بنستخدمش `dangerouslySetInnerHTML` خالص)، ورفض الروابط في نص الرأي.
- الـ `slug` بيتولد ويتتحقق منه بقاعدة صارمة (حروف إنجليزية صغيرة وأرقام وشرطات).

### 7.3 السبام في الآراء
1. حقل Honeypot مخفي، لو اتملا الطلب بيتجاهل بصمت.
2. وقت أدنى بين تحميل النموذج والإرسال.
3. Rate limit: عدد محدود لكل IP (بعد التهشير) في الساعة.
4. الرأي بيدخل `pending` ومبيظهرش لحد الاعتماد.
5. Turnstile اختياري لو السبام زاد.

### 7.4 رفع الصور
- Route Handler `/api/uploads/sign` بيتأكد من الجلسة وبيرجّع توقيع بمعاملات محددة (مجلد ثابت، صيغ مسموحة jpg/png/webp، حد أقصى للحجم).
- الرفع بيتم من المتصفح مباشرة لـ Cloudinary، وبعدها Server Action بتحفظ `publicId` والأبعاد في المشروع.
- لما صورة تتحذف من اللوحة، بتتحذف من Cloudinary كمان.
- `next.config.ts`: نضبط `images.remotePatterns` للدومين بتاع خدمة الصور (مش `images.domains` لأنه متراجع عنه).

### 7.5 الإعدادات العامة
- Headers أمنية من `next.config.ts` (`X-Frame-Options`، `X-Content-Type-Options`، `Referrer-Policy`، وCSP مناسبة).
- كل الأسرار في متغيرات البيئة ومفيش حاجة منها بتتسرب للـ client.
- مسارات `/admin` ما بتتفهرسش (`noindex`). ده للحماية مش SEO.

### 7.6 متغيرات البيئة

| المتغير | الاستخدام |
|---|---|
| `MONGODB_URI` | اتصال قاعدة البيانات |
| `SESSION_SECRET` | توقيع الجلسة (طويل وعشوائي) |
| `CLOUDINARY_CLOUD_NAME` ، `CLOUDINARY_API_KEY` ، `CLOUDINARY_API_SECRET` | الرفع والحذف |
| `NEXT_PUBLIC_SITE_URL` | الرابط الأساسي للموقع |
| `ADMIN_EMAIL` ، `ADMIN_PASSWORD` | يُستخدموا في سكريبت إنشاء الأدمن فقط ومبيتخزنوش في الكود |
